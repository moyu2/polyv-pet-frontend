# 狗狗桌宠视觉与动画重构方案 v2

日期：2026-10-23。本文为设计方案，已完成实现并发布到正式观看页，实施结果见 [实现与验收](./狗狗桌宠-v2实现与验收.md)。

## 1. 方案结论

采用“2.5D 玩偶风狗狗 + 透明逐帧精灵图 + 行为状态机 + 观看页安全活动区”。沿用 Vue 2.7、TypeScript、Pinia 和现有养宠接口，重做角色表现层与动作编排。

先完成一只少年犬的待机、左右行走、进食、开心动作，验证实际尺寸的连续播放，再扩展三阶段成长、注视、拖拽和休息。素材质量是第一道验收门槛。

## 2. 当前观感问题与代码证据

以下记录重构前的问题，当前实现与验证结果见文首链接。

| 现状 | 证据 | 影响与改法 |
| --- | --- | --- |
| 每阶段使用 idle/eat/happy/hungry 四张 SVG | `src/components/pet-panel/pet-sprite.vue`、`public/assets/pets/manifest.json` | SVG 内已有呼吸、摇尾等局部动画，但没有连续迈步、咀嚼、转头帧；外层又整张浮动、挤压，容易像贴图。改用真实姿态序列，外层仅承担位置。 |
| 闲逛随机改变 x/y，2.6 秒过渡 | `pet-desktop-pet.vue` 的 `deskStyle`、`scheduleWander()` | 待机图在整页滑动，没有朝向和步态，且可能进入播放器、聊天区。改为沿安全边缘行走，并同步脚步和位移。 |
| 喂养返回后立即用新宠物覆盖当前形象 | `use-pet-store.ts` 的 `feed()` | 升级时先显示新阶段再播放成长效果。将业务状态与屏幕上的阶段分开，旧阶段吃完后再切换。 |
| 动作用多段固定定时器切换 | `use-pet-store.ts` 的 `animationVersion` 与 `setTimeout()` | 时长与素材分离，连续操作可能覆盖动作。由播放器完成事件驱动动作链。 |
| 资源失败回退蛋或史莱姆 | `pet-sprite.vue` 的内置回退 SVG | 狗狗突然换物种，破坏角色一致性。改为狗狗静态封面，加载失败保留同物种。 |
| 旧 PNG 图集只有关键姿态 | `deliverables/pet-visual-kit-v1/manifest.json` 的 `key-poses-with-css-motion` | 换回旧 PNG 不能补足连续动作，需要制作新的帧序列。 |

检查范围为当前源码、素材及仓库已有观看页截图；本次没有重新运行或测量线上页面。

## 3. Codex 桌宠有哪些可借鉴之处

核对本机 Codex 附带的 `hatch-pet` 规范：v2 为透明 PNG/WebP，1536×2288，8 列×11 行，每格 192×208；前 9 行为标准动作，后 2 行为 16 个顺时针注视方向。标准动作逐帧配置时长，待机、移动、等待等含义明确。其制作流程强调角色母版、按动作行生成、确定性拼图和连续播放验收。

来源：

- [OpenAI 官方 Pets 文档](https://learn.chatgpt.com/docs/pets)：公开说明了精灵图、自定义宠物、活动反馈及减少动画模式。

注意版本与用途：当前公开网页列出的上传尺寸为 1536×1872，与本机 v2 规范不同，不能将其混为同一个上传合同。本项目是观看页内的桌宠，借鉴素材生产方法，自建 Web 播放器；以下架构是本项目的设计，不是对 Codex 私有渲染实现的断言。

Codex 的 `running` 表示任务处理中，左右移动另有 `running-left/right`。养宠业务必须专门绘制进食、饥饿等动作，不能把处理任务的动作直接当成吃饭。

## 4. 视觉方向

### 4.1 角色母版

推荐暖金色垂耳狗，奶油色口鼻、胸口及额头标记；保留当前狗狗的主要识别特征。以圆润体块、柔和体积光和低反光的玩偶质感表达，减少粗黑描边。方向稿呈现了较多绒毛细节，正式小尺寸动画需收敛为大块绒感，避免毛发闪烁和轮廓噪声。

- 幼犬：瘦小窄身、细短腿，耳朵相对显大，保留健康稚嫩的体型。
- 少年犬：胸腹饱满、身体匀称、腿长适中，精神活泼，避免细腰和过长细腿。
- 成犬：胸背厚实、口鼻成熟、尾巴丰满，保留同样的脸部特征和毛色。
- 狗狗第一阶段界面文案显示“幼犬”，通过前端适配保留后端 `egg` 编码。
- 单格有效轮廓尽量占约 80% 高度，留出耳尾及跳跃空间；先在桌宠实际尺寸下判断脸部是否清晰。

角色方向稿见 [dog-visual-direction-v2.png](./dog-visual-direction-v2.png)。它用于确认材质、比例和角色一致性，不是可直接裁切上线的动画图集。图片由内置 imagegen 生成，完整生成提示词保存在 [dog-visual-direction-v2-prompt.txt](./dog-visual-direction-v2-prompt.txt)。

### 4.2 页面中的呈现

- 实际 PC 默认显示框为 136×119 CSS px；窄屏为 104×91 CSS px，形象本身保留三阶段体型差异。
- 默认停在播放器外侧的页面空闲区域；手机放在内容下方或专用小停靠位。
- 常态只露出狗狗和轻量落地阴影。积分、经验、饱食放在点击展开的约 240 px 气泡中；只在实际积分变化时短暂展示到账提示。
- 点击有抬爪或抬头反馈；拖动时有独立悬空姿态，落下后回到最近的安全停靠点。
- 提供收起入口，关闭后保留一个轻量唤回按钮；不能只能依靠悬停发现操作。

## 5. 动作设计与素材合同

### 5.1 完整目标动作

以下帧数和时长是本项目初始制作规格，可在连续播放验收后调整。

| 动作 | 帧数 | 画面要求 | 使用方式 |
| --- | ---: | --- | --- |
| idle | 6 | 呼吸、眨眼、小幅尾摆，脚底稳定 | 低干扰待机；眨眼间隔可插入静止停顿 |
| walk-right | 8 | 右朝向、四肢交替、耳尾随动 | 安全边缘短距离移动 |
| walk-left | 8 | 左朝向、同等步幅 | 只有标记完全对称时才允许镜像 |
| greet | 4 | 抬头或抬爪，再自然放下 | 点击、首次出现，单次播放 |
| eat | 8 | 低头靠近食物、张嘴咀嚼、抬头 | 接口确认喂养成功后播放，约 1.2～1.6 秒 |
| happy | 6 | 摇尾、短促小跳、落地稳定 | 喂完或成长后播放一次 |
| hungry | 6 | 耳朵微垂、轻舔嘴、期待目光 | 饱食度低时的低频表演，避免全身摇晃 |
| sleep | 6 | 趴下、闭眼、腹部轻微呼吸 | 长时间无操作后休息 |
| dragged | 6 | 四肢轻收、耳尾下垂、轻微摆动 | 拖拽期间，停止自主移动 |
| look | 16 个静态方向 | 以眼睛、头和颈部带动视线 | 指针靠近后短暂注视，中心死区回到待机 |

成长由“旧阶段准备 → 轻量遮罩 → 新阶段出现 → 开心落地”组成，单独编排，不把成长特效烘焙进每张狗狗图片。

### 5.2 图集与元数据

实际版本采用 256×224 单格和 8×11 网格：9 行业务动作加 2 行注视方向，较宽的单格适配狗狗横向轮廓和尾巴。每阶段独立一张透明 WebP，并在工作目录保留 PNG 母版。

这只复用了几何规格。动作行已经按养宠重新定义，项目元数据采用 `schema: "polyv-pet/2"`，不使用 Codex 的 `spriteVersionNumber` 冒充可直接导入 Codex 的宠物包。

元数据至少包含：`schema`、素材版本、物种、阶段、图片尺寸、帧矩形、每帧时长、循环方式、逻辑落脚点和嘴部挂点。落脚点用于保持站立稳定；跳跃和拖拽的离地高度在其上显式表达，不能通过强行对齐每帧可见最低点消除跳跃。

预览中的食盆、爱心、奖励文字和地面阴影使用独立层；嘴部挂点决定食物飞入终点。狗狗自身图集不包含背景、文字或游离特效。

第一阶段里程碑只制作少年犬的 `idle / walk-left / walk-right / eat / happy`，共 36 帧，不必先填满完整图集。确认效果后再扩展其他阶段和动作，播放器通过显式帧矩形支持两种布局。

### 5.3 生产流程

1. 先定一张角色母版，并核对三阶段比例；所有后续动作引用同一母版。
2. 按动作制作整条帧序列，确保脸、毛色、耳朵、四肢数量和光源一致。
3. 确定性裁切、等比例登记、设置锚点、拼图。避免每帧单独自动放大导致身体忽大忽小。
4. 输出接触表和连续播放预览，先检查小尺寸实际观感，再检查大图边缘。
5. 修复失败的动作行；不要把不同生成批次的单帧随意拼进同一动作。
6. 用透明、浅色、深色背景检查边缘、串帧、断尾和身体透明洞，合格后才接入观看页。

## 6. 前端实现

### 6.1 模块职责

```text
现有 API / Pinia store：服务端业务数据、请求状态
                      ↓ 喂养结果事件
PetDirector：动作优先级、播放链、displayStage、去重与取消
          ├── PetMotion：活动区、朝向、行走速度、拖拽
          ├── PetRenderer：精灵图解码、裁帧、帧时钟
          └── PetEffects / PetBubble：特效、业务信息与操作
```

- `pet-sprite.vue`：逐步替换为 Canvas 2D 精灵播放器。选择 Canvas 是本项目建议；它便于可变帧时长、挂点和分层，当前单只宠物无需再引入游戏引擎。
- `pet-desktop-pet.vue`：保留挂载和交互入口，将随机全页漂移替换为安全活动区与明确朝向。
- 新增 `pet-director.ts`、`pet-motion.ts`、`pet-assets.ts`：分别管理行为、移动、素材加载。公共方法和复杂时序添加简洁设计注释。
- `use-pet-store.ts`：保留余额和服务端宠物状态，移出控制画面播放的多段定时器；通过类型化结果事件交给导演层。

### 6.2 播放与移动

使用一个 `requestAnimationFrame` 时钟，通过累计时间选择帧；帧没有变化时不重画角色。位置用 `transform: translate3d()` 更新，不再持续修改 `left/top`。Canvas 内单独处理朝向，避免把气泡和文本一起镜像。

动作帧率与屏幕刷新率分开：角色通常约 8～12 个姿态/秒；位移可随屏幕刷新平滑更新。行走速度按每个步态周期对应的屏幕步幅计算，建议先调到约 30～45 CSS px/秒，再以滑步检查微调。

实际完整单张 2048×2464 RGBA 解码约 19.25 MiB，因此只持有当前阶段，成长时有界准备下一阶段，播放完成释放旧图。文件大小与解码内存分别检查，不以 WebP 压缩后的文件体积代替内存评估。

页面进入后台后暂停时钟；恢复时重置时间基准，并同步最终阶段，避免一次补跑大量历史帧。减少动态效果模式显示稳定静态狗狗，业务文字照常反馈。

### 6.3 安全活动区

自主行走的安全区来自观看页实际布局：播放器画面及控制条、聊天输入区、商品入口、弹窗、手机底部操作条均为禁入区。基于元素边界和 `ResizeObserver` 更新允许区域。用户手动拖放可以覆盖这些区域，仅限制宠物不超出视口。

第一版使用固定安全停靠位和沿边缘的水平短路径，不做复杂寻路。无安全空间时原地待机；手机默认停靠，不自主跨屏游走。全屏播放器出现时按实际承载元素处理：没有可用外侧区域就暂停宠物展示，退出全屏后恢复。

拖拽以位移阈值区分点击，使用 Pointer Capture 并处理取消、捕获丢失、失焦和卸载。拖动时跟随指针，释放后保留用户位置；聊天更新、滚动和布局变化不再触发自动避障重定位，缩放窗口时只收回到最近的视口边缘。拖拽结束后短暂休息再启用闲逛。

注视方向采用 16 扇区加中心死区、边界滞后；距离较远时回待机。鼠标无须驱动整只狗不停旋转，移动端保持自然默认朝向。

### 6.4 喂养与成长时序

```text
点击食物 → 立即做期待反馈，同时发送请求
失败     → 显示失败原因 → 回待机或饥饿，不播放成功奖励
成功     → 立即更新真实余额/经验
         → 旧 displayStage 播放 eat
         → 若成长：过渡遮罩 → 切换 displayStage → 新阶段 happy
         → 否则：happy
         → 按当前饱食度与活动环境回到合适状态
```

业务状态即时更新，`displayStage` 由动作链控制；数值可以在播放过程中显示最新值。刷新恢复直接显示服务端阶段，不重播历史喂养。下一阶段素材准备失败时，也必须最终展示对应阶段的静态狗狗封面，不能一直卡在旧阶段或切换为史莱姆。

`actionId` 用于动作去重，返回 `idempotent=true` 时不重播成功动画。首版在请求与本次主动作链结束前禁用重复喂养，避免无界排队；导演层仍允许收起、关闭和卸载取消播放，取消后必须同步到最新业务阶段。

优先处理：隐藏/卸载 → 用户拖拽 → 已确认的喂养与成长 → 问候/注视 → 饥饿/休息/闲逛。用户打断主动作时保存必要完成状态，结束后收敛到最新阶段，不能丢失业务结果。

当前代码打开气泡时刷新状态，没有主动接收积分到账事件。第一版只对已经确认的状态差值或喂养结果做反馈；独立的即时积分到账庆祝需要后续明确事件来源，不能仅靠视觉层假定已实时感知平台奖励。

## 7. 实施顺序与验收

| 顺序 | 交付物 | 进入下一步的条件 |
| --- | --- | --- |
| 1. 定视觉 | 角色母版、三阶段比例稿、本次方向稿 | 实际显示尺寸下脸部和轮廓清晰，确认风格 |
| 2. 验证动作 | 少年犬五动作 36 帧、独立预览 | 走路有步态、吃饭有咀嚼、尾巴自然、首尾循环稳定 |
| 3. 接入观看页 | 播放器、导演层、安全停靠、喂养链 | 真实观看页内行为与数值一致，关键操作区可正常使用 |
| 4. 补齐成长 | 三阶段、饥饿/休息/拖拽、16 向注视 | 角色一致，成长切换时机正确，无资源缺失导致换物种 |
| 5. 发布验收 | 录屏、素材检查表、体积/内存/播放性能记录 | 核对 PC/手机、深浅底、后台恢复、重复请求和加载失败 |

必须看到的验收证据：

- 连续播放待机与行走，脚底不乱跳，位移与迈步同步，动作结束不突然换脸。
- 从阈值前喂到成长，录屏确认旧犬吃完后才出现新犬，业务数值来自接口。
- 连续点击、请求失败、幂等响应、播放中拖拽、切后台、刷新等情况下，余额与阶段最终一致。
- 在 375 px 手机宽度及桌面观看页上，气泡完整可操作，播放器控制条和聊天输入区不被宠物覆盖。
- 加载慢、单动作图丢失和下一阶段图损坏时，仍能显示同物种封面和操作反馈。
- 页面运行期间只保留必要动画与监听，卸载后清理；性能目标以实际设备录制结果验收，不预先宣称已达成。
